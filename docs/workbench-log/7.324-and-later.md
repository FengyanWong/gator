### 7.327 CircuitGPS: structured measurement programs and joint circuit/spec/parameter attention (2026-10-12; user: "Build the new encoder")

The user requested implementation after reviewing the encoder design, explicitly without a detailed ablation campaign.
A new `circuit_gps` architecture was added alongside the five retained encoders. It combines terminal/direction-aware
local attention, distance/terminal-biased global attention, Pre-LN gated residuals and repeated interactions among
nodes, specs, parameter groups and conservative electrical motifs. No instance IDs become neural input categories.

**What the old input could not distinguish.** Pooling the spec set lost which circuit node each spec measured;
coarse descriptors also conflated rise/fall time, maximum/minimum and average/RMS. A spec exactly on its bound did
not expose its reward scale. The new `spec-program-v1` layout retains one token per active spec, scale and each
signed margin, together with an ordered measurement tree whose leaves bind to nets, current terminals, excitation
sources or size-formula members. Operations, operand order, constants and units persist; unsupported syntax and
opaque analyzer results are explicit unknown tokens, unresolved addresses have separate validity. Validation reports
unknown program parts instead of implying that their semantics are understood.

**Parameters and physics.** Shared group tokens retain legal-domain coordinates, integer/log/step information,
binding ratios and membership. Every block refreshes their device context. With operating-point input enabled,
masked gm/Id, gm/gds, overdrive, saturation headroom and Vds/Vdsat supplement the existing raw features. Hierarchy
uses conservative shared-source pairs away from supply/ground, diode-connected mirror groups and explicit parameter
ties; known higher-level functions can be supplied as member lists. It does not label arbitrary common-ground pairs
as differential amplifiers or create every possible pair of a large mirror group.

**Policy and critic.** The shared actor emits one distribution per independent active parameter group. Each critic
injects its proposed actions into both group tokens and bound devices before processing; actor, Q1 and Q2 keep
independent weights. Attention plus token-type sums/counts preserves multiplicity at readout. SAC, reward, action
legalization, proposal semantics, entropy and real backends are unchanged. Attention remains isolated by circuit.
Raw program/binding/physics tensors count toward the existing bounded observation cache; distance caching has its
own 64-entry/32 MiB bound. No learned embeddings are cached.

**Workbench.** The sixth template, “CircuitGPS — joint spec and parameter attention”, selects Structured inputs.
Structured + Transferable 2 combines these with the existing PDK, bench, net-role and OP inputs. Existing tasks are
not rewritten and Graph Transformer remains the default. New runs, offline archive pools/training, saved contracts,
model restoration, structure tables and local/global/parameter attention inspection all support CircuitGPS. Unsupported
encoder/input pairings are rejected before runs. The browser fixture builder now makes a third synthetic model.

**Compatibility.** Model ID `circuit_gps`, architecture version 1, spec layout `spec-program-v1`, descriptor/program
version `measurement-program-v1`. The optimizer digest changes from `6724e52b9ce8bcbb...` to
`e29b39e1650cbe93f271e28f9955f648504c4f84554b08196989b40c68421ebf` (uncommitted). Retained models still
fine-tune/evaluate under existing checks; exact resume of earlier checkpoints needs their historical runtime.
An explicit comparison against HEAD checked all five retained encoders, both legacy input layouts and actor/critic
paths: identical initial state tensors and bit-for-bit outputs. Existing frozen evidence and simulation runtimes were
not changed.

**Verification.** Encoder/input/cache/checkpoint and workbench API/model regressions, plus new behavior tests for the
formerly colliding inputs, missing values, circuit isolation, permutation/renaming, action gradients, hierarchy,
checkpoint next-update restoration, a complete MOCK run and offline training. TypeScript type-check passes. Scratch
browser checks `network_panel_check` and `encoder_models_check`: **81 checks passed**, no flaky checks; they built
only into a temporary directory, not the live frontend build. The affected preset test's old GraphGPS-only RWSE
expectation was updated for CircuitGPS. The sandboxed API TestClient hung; the same isolated tests run normally
outside that socket-restricted sandbox. No real simulation, paid service, ablation campaign, commit or push.

Implementation and use: `docs/circuit-gps.md`. New modules: `opt/models/circuit_gps.py`,
`opt/models/measurement_program.py`, `wb/spec_programs.py`; new tests: `tests/test_circuit_gps.py`,
`tests/workbench/test_wb_circuit_gps.py`. Registry, model input/view, pretraining, validation, preset, inspector,
frontend template/restoration and browser-fixture integration were updated in place, preserving concurrent work.

### 7.333 A size the optimizer's grid does not hold as a start is said in words before a task is saved or a run is tried (2026-10-12, session "Encoder experiment plan setup"; user: "what is the size grid fault", then "option 2")

**The fault, as record 7.320 met it.** A varied row has a lower bound, an upper bound and a step, and the optimizer
counts the row's grid in steps from the lower bound, in floats: `floor((upper - lower) / step + 1e-12)`. For some
bounds the division lands a hair under a whole number - 13.75 to 137.5 um in 5 nm steps gives 24749.999999999993 - and
the grid ends one step under the upper bound: at 137.495 um. For the search that is one 5 nm step lost at the top of
the row. For a task it is a trap: a cell whose size sits exactly on such a bound differs from its own start design
(`CircuitGraph.assignments` moves 137.5 um to 137.495 um), and every run of the task, its automatic baseline first, is
refused with the optimizer's "Initial backend parameters differ from the reference graph" - no row, no number, no
advice. `compile.grid_top` (round 5) covers only the opposite case, a top that lands above the bound.

**The three ways put to the user:** leave it; a guard in the workbench only; or correct the count in the optimizer
package, which changes its source digest and makes the top value newly reachable on the rows concerned. The user took
the second.

**What is built** (workbench only; nothing in `src/analog_optimizer`, the digest is untouched).
- `start_grid.py` (new, a leaf): `start_off_grid(lower, upper, step, value)` returns the value the optimizer would
  start a row from when that is not the circuit's own value, else nothing. It does not copy the count: it asks the
  package's own `ParameterGroup.project` on a group of these numbers, with the tolerance of the package's own start
  check, so it says what a run would do and cannot drift from it. `start_words` writes the message - the row, both
  values in the row's units, what to set.
- `compile.build_graph` raises with those words when a varied group's circuit value is not its own start. Every
  path compiles the rows against the circuit: **Save task** refuses before anything is written (its profile writer
  turns a compile refusal into its own), **Start**, **Baseline simulation** and **Check now** say the same.
- `validation` marks the row: an error `start_off_grid` on the Parameters row, with the same words, in the page's
  list of blocking issues and in `validate` on the command line.
- The words, for the row that met it: "w_pass: the circuit has 137.5 um on DUT/MP.w, which is this row's upper bound,
  but the optimizer's grid for the row (5 nm steps from 13.75 um) ends at 137.495 um, one step under that bound. A run
