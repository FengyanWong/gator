### 7.479 A connection can say that its license server is not asked, so a real start no longer asks twice (2026-11-06, Claude; user: "Yes, build it", to the next fix offered after record 7.478: the license question asked twice at every start)

**What happened at every real start from the page.** The gate before a real run tests the connection in full, the
license part included. On this installation that part has never read anything but `unknown`: all 106 full tests in the
backend's log, 20 September to 2 November, ended `license_not_checkable`. An unknown part needs an acknowledgement, so
the start was refused, the page asked whether to go ahead with a Spectre license that is "not known to work", and the
repeated request was tested in full a second time. The question's advice, to press Full test, could not change the
answer.

**Why the license part reads nothing.** The bridge's license check (`SpectreSimulator.check_license`, bridge 0.8.0) runs
`lmstat -a` on the simulator host and keeps only the lines of licenses that are in use at that moment: a line without
"licenses in use", and a line with "0 licenses in use", is dropped before GATOR sees anything. An uncounted license has
no such line at all, a license server on which no Spectre license is in use just then gives none either, and neither
does a host without `lmstat`. The three cannot be told apart from what the bridge returns, and none of them is a fault.

**The setting.** A Virtuoso connection may say `"license_check": false` in its entry of the connection file
(`connection.py`: `run_layers`, `_record_spectre_results`). The license part of its full test is then `not_applicable`,
with the reason `license_not_asked` and a note that says so: not ok, not failed, not unknown. The gate before a real run
neither blocks on it nor asks about it, so a start is tested once. The bridge's call is still made, because it is also
what finds Spectre: a missing Spectre is named and stops the start as before. Only the JSON value `false` switches the
question off; any other value asks as before. For such a connection the full test's sentence no longer claims a free
seat: "Connected: SSH tunnel, Virtuoso CIW, session and Spectre are OK. The license server is not asked on this
connection." (`bridge_connect.summarize`; a Virtuoso on this machine has its own wording). The next step shown for
`license_not_checkable` now says what the check can and cannot read, and names the setting. What is given up is the one
thing the snapshot can report, that every seat is taken: a simulation that gets no seat then fails in its own words, and
the run's stop after repeated infrastructure failures ends it.

**Not changed.** The default: a connection that does not say so is asked as before, and its unknown license part still
needs the acknowledgement. The page: its question keeps its words, and no page file changed. This machine's connection
file: the setting is the user's to make, by hand or on their word, and this record does not set it; each session of a
connection has an entry of its own. Nothing under `src/analog_optimizer/` or `frontend/`; no server, simulation or
tunnel was started, and the simulator host was not contacted.
