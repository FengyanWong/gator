### 7.105 Probes lose `conditions` and `aggregation`, with the migration (2026-09-29, session "More columns feature", user: "what does the more columns do?" ... "what migration can you delete those columns" ... "yes delete them with the migration")

**Why.** The two Probes columns behind "More columns" were to name the test conditions a probe is measured under and
how its values there combine (`nominal_only` / `worst_case` / `mean` / `min` / `max`). No run ever used them: anything
but `["nominal"]` / `nominal_only` was a run blocker (`nominal_only_backend`, whose text still said PVT scheduling is not
implemented), and since reward v2 (`1135b8b`) the test conditions are chosen for the whole run (`run.conditions`,
"Training conditions") and per spec (`nominal_only`, "Judged at"). The line "The Probes tab keeps `conditions` /
`aggregation`" of `docs/plan-robust-reward-and-network.md` (section 6.2) is superseded by this decision; neither
`docs/brief-reward-v2.1-for-astra.md` nor the Monte Carlo plan uses the two columns (checked before the edit).

**What changed** (the recipe of 7.92):
- `schema.py`: both fields are out of `MeasurementDefinition` and in `RETIRED_MEASUREMENT_FIELDS` with their defaults
  (`["nominal"]`, `nominal_only`), so the before-validator drops them whatever they say and `_hashed` still sees them at
  those defaults. `ADVANCED_COLUMNS` keeps only the Specs three: the Probes tab has no "More columns" button any more.
- `validation.py`: the `nominal_only_backend` blocker is gone (nothing left for it to check).
- `engine.py`: a probe's aggregate metrics row still says `aggregation = nominal_only` (`PROBE_AGGREGATION`), the only
  value it ever had, so results tables read as before; `storage/tables.py` unchanged.
- `store.ts migrateConfig`: the browser strips the two keys like the other retired Probes keys.
- `conditions` was the editors' only JSON-typed column. The generic JSON cell of `Editors.tsx` stays for any later list
  field; no browser check types into one any more.
- Docs: `docs/workbench.md` ("Fewer columns ..." section). Tests: `test_wb_retired_columns.py` (new: the two keys are
  dropped whatever they say, stated at their defaults they give the G7 task hash; Probes has no hidden column),
