### 7.389 The final save is skipped when a run stopped while it was being prepared: the reason stands alone (2026-10-23, Claude session "Skip the final save when a run never prepared"; user: "Fix: in finalization, skip the final save when the engine has no `checkpoints` attribute (preparation did not get that far), recording why in the summary if useful")

**Request.** The user described the fault (2026-10-23): when `engine_preparation.prepare` raises before it creates
`engine.checkpoints` - for example the guard "Unresolved physical launch intents/leases must be reconciled before
resume; no lanes opened", which fires when a real run that was killed hard is continued - `finalize` still calls
`engine._relabel_unchanged(kind) or engine._checkpoint(kind)`, and the status error reads "...; final save failed:
AttributeError: 'RunEngine' object has no attribute 'checkpoints'". The run already fails safely (nothing simulated), so
this is noise that hides the real reason behind a second error. Asked: skip that save, say why in the summary if useful,
a test in `tests/workbench`, the full regression, nothing committed without the user's word.

**What was wrong.** `finalize` saves whenever the dataset is healthy, the budget ledger exists and nothing is in flight.
Preparation makes the ledger early and opens the save points (`engine.checkpoints`) only after a resume's checks, so a
run that stopped in between - the unresolved-launch guard above, a save point of another run or task, missing rehearsal
state - ended with a second error. Seen on both killed-run checks of the archive comparison's step 5
(`e2e-ota5-T0-killed` and `e2e-sky130-T0-killed` under `~/gator/e2e-outputs/bo-mobo-rl-2026-10-23/`): `status.json` and
`run_summary.json` carried the tail, `logs/errors.jsonl` a `final_save_failed` row after the `exception` row, and the
summary said `persistence_ok: false` although every row was written (61 of them in the OTA5 run). The order has been the
same since at least `1135b8b` (2026-09-27); the refactor that moved the code into `engine_preparation.py` and
`engine_finalization.py` (`75f6dda`) kept it.

**Change.** `engine_finalization.finalize`: when the engine has no save points (`engine.checkpoints` missing), the final
save is skipped; the dataset is still flushed first, since a resume can write the rows of interrupted evaluations before
it stops. `run_summary.json` then carries `output.note` (`SAVE_SKIPPED_NOTE`): "No save point was written: the run
stopped while it was being prepared, before it opened its save points. Those already in the run folder are unchanged."
The key appears only then; every other run's summary is as before. The status error is the original one,
`persistence_ok` stays true, and `resumability` / `latest_checkpoint` stay `none` / null as before: this segment wrote
no save point, Runs' "Can continue" is unchanged, and while the lease is unresolved a Continue is refused anyway.

**Test.**
`tests/workbench/test_wb_crash_counters.py::test_a_resume_refused_for_an_unresolved_launch_reports_only_that_reason`
(about 12 s; the first workbench test of the guard itself): a MOCK worker process killed by SIGKILL after five commits
(a save point every four), the run's `data/_journal/unresolved-launch-leases.json` written as a real backend's
unconfirmed launch leaves it (the MOCK backend never writes one), then a resume. It asserts that the status and summary
error are exactly the guard's message, that `errors.jsonl` holds only the `exception` row, that `persistence_ok` is true
and the note is there, and that the save points (names and modification times) are untouched. Before the fix it failed
with exactly the observed tail.

**Regression.** `OMP_NUM_THREADS=1 python -m pytest -q -n 4 --dist loadgroup` in the tree: 2,752 passed, 1 skipped
(2,753 collected), 453 s, 2026-10-23 18:08-18:16. Four workers instead of twelve: a peer's wall-time measurement
