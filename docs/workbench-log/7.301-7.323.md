**What a rename is.** A saved model already has one (record 7.225: a Name box and Rename in its Details, a label file
beside the run, the run folder untouched). A task had none. A task's name is its key (`real:<name>`): its folder, its
Virtuoso cell, the task of every recorded run and saved model - and a run's archive is checksummed, so a recorded run
can never be rewritten to another key. So a task's rename is the same kind as a model's and a folder's: **the name it
is shown under**. The key, the files, the cell and every run and model stay; the windows show the new name, and new runs
of the task are filed under it.

### 7.304 Bayesian optimization as a comparison method: `run.optimizer: "bayes"` in a configuration file - the same run but for who proposes the designs (TuRBO-1, torch only); the network is neither asked nor trained (2026-10-10, session "Encoder experiment plan setup"; user: "different opt on one circuit from scratch (sac bayesian)", "delete random search in step 2", and "A": the optimizer is written while step 1 runs, with small tests only)

**Why.** Step 2 of the transfer experiment (plan 7.301, section 6.2) asks whether SAC is better than Bayesian
optimization from scratch on the published AgenticSizing LDO, and the workbench had SAC only (record 7.226). The four LLM
methods of 7.116 were removed on the user's word that SAC is the page's one method; this is not a fifth box on the page
but a comparison method a configuration file names.

**How it joins a run.** Actions in this environment are absolute designs (`absolute-group-v1`: a number in [-1, 1] per
parameter group), so another proposer fits where the policy is asked. `run.optimizer` (`sac` | `bayes`, default `sac`,
hashed as absent for SAC: every configuration before it keeps both hashes). With `bayes` the engine
- draws the random warm-up designs as always, from the run's own generator: the same designs as the SAC run of the seed;
- then asks `bayes.Proposer.propose()` instead of `learner.act` (action source `bayes_opt`, phase `search`);
- tells it every finished step design and its reward, the warm-up's included; a design without a reward counts as the
  worst seen;
- never updates the network (`_updates_due` is false): no learner update is recorded, the saved model is the untrained start.
Budget, lanes, episodes with their start checks, retries, the tables, best design and save points are the run's own code,
unchanged. From scratch only (`bayes_needs_scratch` in validation; the engine refuses a resume in words): the search
state lives in the run's process. The manifest says `architecture.optimizer` for such a run and nothing new for a SAC run.

**The method** (`src/gator_workbench/bayes.py`, torch only - the pinned environment holds numpy, torch and PyG, and no
package was added): TuRBO-1 (Eriksson et al., NeurIPS 2019) asked for one design at a time, as the lanes free up.
A Gaussian process, Matern-5/2 with one length scale per variable, fitted by maximum marginal likelihood on the designs of
the current trust region (the newest 600 and the best, so a fit stays under a second); a box around the best design
whose sides follow the length scales, doubled after 3 improvements in a row, halved after max(4, variables) designs
without one, begun again from fresh random designs when smaller than 0.8 %; Thompson sampling - one joint draw of the
process over up to 2,000 candidate designs in the box. Its initial designs are 2 x variables in all, the run's warm-up
designs counted.

**Checked before any simulation** (no Spectre run was made for this record):

| Function (its best value) | Designs | Bayesian | Random search |
|---|---|---|---|
| Hartmann, 6 variables (3.322; second best 3.203) | 150, three seeds | 3.202, 3.201, 3.321 | 1.37, 2.77, 2.12 |
| Ackley, 20 variables (0) | 400, two seeds | -2.32, -2.02 | -11.09, -10.40 |
